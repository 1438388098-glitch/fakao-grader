# 判分一致性评测协议

> 目的：把「判分稳定」从机制声明变成可复现的数字。**本协议已定义、尚未在真实题库上执行**——当前仓库内没有任何评测数字，以下是首次执行的操作手册。

## 方法

对**同一份作答**独立批改 N 次（默认 N=10）。每次批改必须：

1. 开**全新会话**（不携带任何上一次批改的上下文，避免自证一致）
2. 只提供：评分作业单（`extract.js` 产出，固定不变）+ 作答文件
3. 报告产出后，逐采分点抄录判定序列（✓/△/✗）与总分

## 指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 点级判定一致率 | 任意两次批改中，同一采分点判定相同的比例（按次对两两比较取均值，或与首次批改比较取均值并注明口径） | ≥ 90% |
| 总分标准差 | N 次采分点得分的样本标准差 | ≤ 1.5 分 |
| 预估带重叠率 | N 次考场预估带两两有交集的比例 | ≥ 80% |
| 类型误判数 | 结论点/依据点/分析点类型标注不一致的点位数 | 记录并归因 |

## 判读

- 不一致点先看**是否命中白/黑名单**：命中白/黑名单仍不一致 → SKILL.md 规则缺陷，修规则
- 白名单等义判断不一致 → 补充校准样例或扩白名单
- 分析点（涵摄程度）不一致率天然偏高 → 允许放宽目标，但须在报告口径中单独列出

## 执行前提

- 备考工作区（真实题库 + 至少 1 份真实作答）
- 每次批改约消耗一次完整报告的 token；N=10 × 1 题为一轮最小验证
- 结果回填到本文件末尾的「执行记录」小节（日期、题目、N、三项指标、结论）
